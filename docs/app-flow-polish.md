# App flow improvements — 2026-11-02

- Inyeon: shared New / Likes / Letters navigation; board and profile remain secondary. A matched pair opens its exact conversation. Push notifications carry the validated conversation ID.
- Photos: sequential partial-failure processing continues after a failed file. Failed files alone can retry in the current page. Memory-only checkpoints reuse encoded bytes, storage path and completed transfer while retrying registration. Account changes clear pending UI and reject stale work. Approval state stays server-controlled.
- Messages: authenticated membership list gates deep-link opening; request generation/account guards prevent delayed room responses overwriting another room. Latest 200 messages are shown in chronological order. Contact/read-pass purchases are collapsed, with prices retained.
- Practice: the main objects and tower remain visible; other rooms expand on demand. Entering practice from another main section resumes the last allowed practice route. Re-tapping the practice main tab still returns to its main page. Existing selected-object persistence and daily lotus receipt flow remain intact.
- Checkout: quantity/prices unchanged; account copy and concise cost summary added; payment acknowledgement is guarded against double taps and retries reuse one order ID. An existing committed order is confirmed rather than overwritten. LOTUS_OPEN remains false; sales were not opened.
- Metrics: fixed named events use the existing GA4 command queue, including new-account login metadata, photo success/failure/retry, like/match, first message, checkout and order acknowledgement. No event fields carry personal names, images, IDs or message text; Do Not Track is respected. GA4 can measure unique-user funnels; dashboard stage counts are explicitly labelled as current record counts, not conversion rates. Payment acknowledgement is not labelled completed payment.
- Dashboard: approved-photo/profile/like/pair/conversation counts; total paid revenue uses a server aggregate instead of the newest 40 orders. Monthly chart explicitly describes its 40-order window. New orders status/price index was deployed without deleting existing remote indexes.

Validation: Next.js production build; TypeScript; changed-file lint (warnings only); flow-polish-test; yeon-upload-test; yeon-photo-test (concurrency simulation, not production load); auth-domain-test; daily-lotus-reward-test. Two stale regression mocks were updated for shared bucket configuration, mission status and TSX module loading. No production user photos, public profiles, purchases or wallets were created during testing.

Mobile UI: common navigation routes, overflow, practice expand/collapse and last-practice return. Checkout sale closure verified. Signed-in upload/checkout edge cases were exercised using controlled module and real-handler tests, not real accounts or transfers.
