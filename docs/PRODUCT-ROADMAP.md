# 화두 제품 로드맵 — 로그인부터 결제까지

## 현재 확인된 기반

- 인증: Firebase Authentication의 Google 로그인을 이미 사용 중이다.
- 데이터: Firestore와 Firebase Admin API가 연결돼 있다.
- 연꽃: 지갑과 주문 대기열은 있으나, 현재는 계좌이체 확인 후 관리자 지급 방식이다.
- 결제(PG): 실제 카드·간편결제 승인 연동은 아직 없다.

## 진행 순서 (이 순서를 바꾸지 않는다)

### 1. 로그인 설계

목표: 사용자는 로그인 없이 화두와 수행을 체험하고, 기록·커뮤니티·연꽃이 필요할 때만 자연스럽게 로그인한다.

- Google 로그인 유지
- 카카오/Apple/이메일 로그인 추가 여부는 실제 유입 채널을 확인한 뒤 결정
- 계정이 필요한 행동과 필요 없는 행동을 표로 확정
- 로그아웃·계정 삭제·개인정보 동의 흐름 점검

### 2. 첫 화면과 온보딩

목표: 첫 방문자가 설명을 읽지 않아도 `화두 받기 → 수행 → 기록`을 경험한다.

- 첫 화면 CTA 하나: `새 화두 받기`
- 첫 화두를 받은 뒤 3문장 이하의 맥락 안내
- 가입 유도는 화두 기록/커뮤니티/연꽃처럼 저장이 필요한 순간에만
- 완료율, 로그인 전환율을 측정할 이벤트를 설계

### 3. 재화와 과금 정책

목표: 연꽃이 무엇이고 언제 쓰이는지 결제 전에 명확히 이해시킨다.

- 연꽃의 획득·사용·환불 규칙 확정
- 무료 지급분과 유료분을 데이터에서 구분
- 가격표·이용약관·환불 기준을 정리

### 4. 결제대행(PG) 선정 및 연동

목표: 카드와 간편결제 승인 결과를 서버가 검증한 뒤에만 연꽃을 지급한다.

- 후보 비교: PortOne(여러 PG·간편결제 통합), 토스페이먼츠(직접 계약·운영), 카카오페이(카카오 사용층 중심)
- 실제 선택 전에는 사업자 정보, 예상 월 결제액, 필요한 결제수단, 정산 계좌를 확인
- 결제 승인 웹훅 → 서버 검증 → Firestore 지갑 지급 → 영수증/주문내역의 순서로 구현
- 클라이언트가 연꽃 수량을 직접 늘릴 수 없게 서버 단에서 일회성 결제 ID를 검증
