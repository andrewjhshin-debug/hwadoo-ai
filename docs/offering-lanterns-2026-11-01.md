# Selected offering-sheet design only

Apply only the approved offering interaction and lantern family, not the full app redesign. The chooser remains the five existing offering kinds; remove its premature one-lotus price badges because public/private prices differ. The writing sheet shows a single wish field, optional name disclosure, existing private/public choices with their exact prices/durations, and a thumbnail color selector for lanterns. Users may preview before signing in; actual creation still requires authentication and the existing atomic server transaction.

Three new rounded lotus lanterns: pink, warm gold and mint. All have a glowing ivory center, broad soft overlapping petals, a small brass loop/cap and bottom fitting, with no rectangular paper tag. Existing story access and accessible names remain. Existing documents without a color use a stable seed-derived choice. Explicit choices persist as `lanternColor`, feed the actual hall rendering and optimistic placement, and are returned on idempotent retries. Other offering kinds ignore this field. Prices, burn days, wallet debit and visibility defaults are unchanged.

Built-in ImageGen prompt: one transparent three-color atlas, three same-shape round glowing lotus lamps in a horizontal row, pink/golden apricot/mint, broad soft translucent petals, warm ivory core, fine brass hanging loop and small brass base; same dimensions, camera and lighting. No cords, paper tags, tassels, text, UI, exterior shadows or scene. References are the selected together-board and the user's color-picker crop. Source: `design/lanterns/source-v1.png`. Runtime files: `public/obj/lotus-lantern-v1/{pink,gold,mint}.webp`. `scripts/prepare-lanterns.mjs` only crops/isolates the connected artwork and registers three 320×352 sprites.

Validation: TypeScript; API/storage tests cover all three persisted colors, legacy fallback, invalid colors, unchanged atomic price, retry without double debit/recolor, insufficient funds and authentication. Browser checks at390×844 and360×640: all images loaded, color selection updates, wish entry enables the action, and at360×640 the complete sheet has 0px internal overflow with action bottom626px. No live offering or wallet debit was created during browser testing. Targeted lint reports existing Korean component-name hook warnings/errors in CandleHall; the new model/API/renderer files have no new lint errors.
